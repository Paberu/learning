# Линтеры

Установил SonarQube for Intellij Idea, и первое же, что он мне посоветова - это не использовать System.out.println для выведения информации о сложных объектах, на которых держится проект:
1. Standard outputs should not be used directly to log anything
Что ж, я исправил этот недочёт. Тем более, что слишком обширный вывод на экран может затереть начало запуска, а файл журнала - смотря как настроим.
2. The return type of this method should be an interface such as "Map" rather than the implementation "HashMap". Очень интересное замечание. Очень может быть, что хранение будет реализовано в дальнейшем каким-то иным способом, никто не мешает написать мне свой класс словаря, и тогда придётся исправить все файлы, где используется возвращаемый тип HashMap. Проще реализовать свой класс, который реализует интерфейс Map, и тогда менять ничего не придётся. Исправляю.
3. Local variables should not shadow class fields. Водится за мной один грешок, иногда я использую одно и то же имя и для скрытого поля класса, и для локального параметра функции (или временной переменной внутри while в этой функции). Это бывает в тех ситуациях, когда имя кажется достаточно удачным, стандартным и коротким. Исправляю.
4. "Random" objects should be reused. Всё-таки это псевдослучайные последовательности, поэтому, во избежание получения одних и тех же значений в разных частях программы, лучше сохранить этот random в каком-то параметре класса. Исправляю.
5. String literals should not be duplicated. У меня в коде есть случайный выбор величины, которая прирастает на 1 с повышением уровня. Я знаю, что в коде следует избегать чистых числе, строк и прочих сущностей, которые можно выразить, как статические константы в самом начале класса. И тем не менее, когда что-то изучаю или делаю на скорую руку, могу про этот принцип забыть. А потом копипаста, а потом забыл подредактировать, в общем, game over. Исправляю.
6. Strings and Boxed types should be compared using "equals()". Периодически забываю, что через == можно сравнивать только примитивы. Исправляю.
